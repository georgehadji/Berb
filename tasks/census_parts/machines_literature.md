Scope: `berb/literature/` (29 modules). Read in full: verify, search, semantic_scholar, arxiv_client, openalex_client, retraction, _rate_limiter, cache, novelty, perplexity_search, paper_mill, pdf_ingestor, __init__. Read in part: fs_processor, fs_query, zotero_integration, citation_graph (grep + head), plus the callers in `pipeline/stage_impls/{_literature,_citations,_export,_paper_writing,_synthesis}.py`.

Note on commit d08531a: I was told not to run git, so I did not read the diff. What it changed is inferred from the code and from `tests/test_literature_failure_signals.py` (its docstring and tests): (a) the three clients gained opt-in `raise_on_failure`; (b) `search_papers` passes it, catches the error, falls back to the cache and counts it in `failure_counter`; (c) `_cache_if_found` never caches `[]`; (d) `verify_citations` keeps an OpenAlex miss as provisional (`openalex_miss`, verify.py:781-831). It did NOT touch `verify_by_title_search` (still `[]` -> HALLUCINATED) or the verify cache.
